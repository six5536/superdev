<skill name="pack-backport" purpose="Backport Live Edits into the Pack" input="the files or changes to backport, when given" user-input="$ARGUMENTS" output="the pack, matching the live copies, with the round trip green">

<goal persona="release engineer">
You mirror edits made to this repo's live skills, agent files and document templates into the pack they ship from. Backport the files or changes given in the input above.
</goal>

<constraints>
The pack under `/pack/` is the source of truth; the files under `.claude/skills/`, `.agents/` and `knowledge/templates/` are the copies superdev writes into this repo from it. An edit to a live copy ships only when backported into the pack — until then `sync` treats it as drift and rewrites it from the old pack content.
</constraints>

<bootstrap_actions>
<tool_call name="read_file" path=".agents/superdev.md" when="always" />
</bootstrap_actions>

<process_actions>
<step name="FIND THE CHANGES" task="`cargo run --quiet -- status` lists every owned file that differs from the pack. Scaffolds and brand-new files never show there — check `git status` for those" />
<gate check="The changes are presented per file — what changed, and whether to backport it (ship the edit) or let `sync` restore stock (discard it) — and the user has confirmed" on-fail="wait for confirmation before writing anything" />
<step name="MIRROR INTO THE PACK">Mirror into `/pack/`. The pack's layout names the item (ADR-003), so the slot decides the path: a workflow or support skill is `pack/knowledge/skills/<name>/`, one of the three the `skills` capability ships is `pack/skills/<name>/`, an agent file is `pack/agents/<file>.md`, a document template is `pack/knowledge/templates/<file>.md`. Where a file already lives in the pack, put it back where it is rather than deriving the path.</step>
<step name="VERIFY THE ROUND TRIP" task="Verify the round trip: `npm run check:blueprint` exits 0 (every live file byte-matches what the rebuilt binary ships), and `cargo test --workspace` passes" />
</process_actions>


<rules>
<rule level="SHALL">edit `aggregator_content()` in `pipeline.rs` and its tests to change `.agents/superdev.md` — it is generated by that function</rule>
<rule level="MUST NOT">edit a pack file to change `.agents/superdev.md`</rule>
<rule level="SHALL">add, remove, or rename a pack file with no table edit: `build.rs` walks the tree, so the layout is the only declaration</rule>
<rule level="SHALL">add a rule in `classify()` in `content/layout.rs` for a new *kind* of item — not a new item of a kind that exists</rule>
</rules>
</skill>
