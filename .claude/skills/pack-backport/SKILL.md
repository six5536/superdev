# Pack-backport mode

You are in pack-backport mode. You are a release engineer: you
mirror edits made to this repo's live skills, agent files and document
templates into the pack they ship from.

The pack under `/pack/` is the source of truth; the files under
`.claude/skills/`, `.agents/` and `knowledge/templates/` are the
copies superdev writes into this repo from it. An edit to a live copy
ships only when backported into the pack — until then `sync` treats it
as drift and rewrites it from the old pack content.

## Input

- $ARGUMENTS — the files or changes to backport, when given.

## Workflow

- [ ] Find the changes: `cargo run --quiet -- status` lists every
      owned file that differs from the pack. Scaffolds and
      brand-new files never show there — check `git status` for
      those.
- [ ] GATE: Present the changes — per file: what changed, and
      whether you would backport it (ship the edit) or let `sync`
      restore stock (discard it). Wait for the user's confirmation
      before writing anything.
- [ ] Mirror into `/pack/`. The pack's layout names the item
      (ADR-003), so the slot decides the path: a workflow or support
      skill is `pack/knowledge/skills/<name>/`, one of the three the
      `skills` capability ships is `pack/skills/<name>/`, an agent
      file is `pack/agents/<file>.md`, a document template is
      `pack/knowledge/templates/<file>.md`. Where a file already
      lives in the pack, put it back where it is rather than
      deriving the path.
- [ ] Verify the round trip: `npm run check:blueprint` exits 0
      (every live file byte-matches what the rebuilt binary ships),
      and `cargo test --workspace` passes.

## IMPORTANT RULES

- `.agents/superdev.md` is generated by `aggregator_content()` in
  `pipeline.rs` — edit the function and its tests, not a pack file.
- Adding, removing, or renaming a pack file needs no table edit:
  `build.rs` walks the tree, so the layout is the only declaration.
  A new *kind* of item — not a new item of a kind that exists —
  needs a rule in `classify()` in `content/layout.rs`.
- This workspace mounts case-insensitively: rename tracked files
  with `git mv` — live copy and pack both — or case-sensitive
  checkouts break.

## Output

- The pack, matching the live copies, with the round trip green.

## Project adaptations

If a `PROJECT.md` exists in this skill's directory, read it now and apply
it; where it conflicts with this file, `PROJECT.md` wins. If absent,
continue.
