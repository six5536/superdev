# Asset-backport mode

You are in asset-backport mode. You are a release engineer: you
mirror edits made to this repo's live skills and agent files into the
embedded assets they ship from.

The assets under `crates/lib/superdev-core/assets/` are the source of
truth; the files under `.claude/skills/` and `.agents/` are the copies
superdev writes into this repo from them. An edit to a live copy ships
only when backported into its asset — until then `sync` treats it as
drift and rewrites it from the old asset.

## Input

- $ARGUMENTS — the files or changes to backport, when given.

## Workflow

- [ ] Find the changes: `cargo run --quiet -- status` lists every
      owned file that differs from its asset. Scaffolds and
      brand-new files never show there — check `git status` for
      those.
- [ ] GATE: Present the changes — per file: what changed, and
      whether you would backport it (ship the edit) or let `sync`
      restore stock (discard it). Wait for the user's confirmation
      before writing anything.
- [ ] Mirror into the assets. The live-path → asset-path mapping
      lives in the component code: each component's asset tables
      (`FILES`, `SKILLS`, `include_str!` paths) name both sides;
      follow them rather than assuming — the file set changes.
- [ ] Verify the round trip: `npm run check:blueprint` exits 0
      (every live file byte-matches what the rebuilt binary ships),
      and `cargo test --workspace` passes (component tests assert
      against asset content and file sets, so a table or mapping
      miss fails here).

## IMPORTANT RULES

- `.agents/superdev.md` is generated by `aggregator_content()` in
  `pipeline.rs` — edit the function and its tests, not an asset.
- Adding, removing, or renaming a file means updating the
  component's asset table too; an entry missing from a table
  silently doesn't ship.
- This workspace mounts case-insensitively: rename tracked files
  with `git mv` — live copy and asset both — or case-sensitive
  checkouts break.

## Output

- The assets, matching the live copies, with the round trip green.

## Project adaptations

If a `PROJECT.md` exists in this skill's directory, read it now and apply
it; where it conflicts with this file, `PROJECT.md` wins. If absent,
continue.
