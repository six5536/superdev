# Specs

* [CLI Core & Blueprint Engine](spec-001-cli-core-blueprint-engine.md) - design for superdev's setup/management CLI — the manifest, the component model, and init/status/sync/update.
* [AOKF MCP Server](spec-002-aokf-mcp-server.md) - design for the read-side AOKF MCP server — hybrid search, graph, the Rust validator, and the search-first AGENTS.md switchover.
* [Skill Pack](spec-003-skill-pack.md) - design for the skills capability — five skills and the validation hook shipped as owned repo files, with a PROJECT.md extension layer and a per-skill custom opt-out.
* [Blueprint Migrations](spec-004-blueprint-migrations.md) - design for evolving a managed repo — components declare what they own, the lock's leftovers are pruned or released, and CLAUDE.md imports AGENTS.md so Claude Code reads it at all.
* [Workflows Provider Default](spec-005-workflows-provider-default.md) - design for defaulting the workflows capability to mattpocock-skills as materialised repo files, with superpowers kept as a supported plugin-based secondary.
* [Workflows Skill Overrides](spec-006-workflows-skill-overrides.md) - design for provider-carried skill overrides — the mattpocock-skills component materialises embedded replacements, grilling first — installed only where that provider is.
* [Project Templates](spec-007-project-templates.md) - design for project templates — embedded write-once repo scaffolds init seeds a new repo from, token-substituted and disjoint from capability files — with rust-npm as the first, and the fuller knowledge seed it surfaced.
* [Knowledge-Carried Skills](spec-009-knowledge-carried-skills.md) - the aokf component ships the full converted skill set and the workflows capability is dropped; a manifest naming it gets a guided error.
* [Knowledge-Owned Skills](spec-008-knowledge-owned-skills.md) - design for aokf-carried lifecycle skills — aokf-maintain and the validation hook relocate to the knowledge capability, and a new aokf-bootstrap skill harvests a repo's stranded prose and interviews the owner to fill the seeded skeleton.
* [Agent Instructions Layer](spec-010-agent-instructions-layer.md) - AGENTS.md becomes the user's file reached by one ensured import; superdev's instructions live in an owned, fenced .agents/superdev.md aggregating per-capability instruction files, and code-index gains its missing agent wiring.
* [Skills Capability Cardinality](spec-011-skills-cardinality.md) - a capability declares whether it holds one provider or a set; skills becomes the first many-provider slot via [[skills]] entries, with the old single-table shape still parsing.
* [Bash Output Filter Capability](spec-012-bash-output-filter.md) - a new bash-output-filter capability, default provider rtk — a checksummed mise pin, an owned instruction file, and a managed PreToolUse rewrite hook that compacts command output before it reaches agent context.
* [Implements in the Core Vocabulary](spec-013-implements-rel.md) - promote implements/implemented-by into the SOKF core relationship vocabulary — spec bumped to 0.2, validator and graph taught the pair, and the issue-tracker convention realigned.
* [Externally Sourced Content Packs](spec-014-content-packs.md) - superdev's prose content becomes a versioned pack resolved from a pinned source, replacing or layering over an embedded snapshot the binary still carries, so a skill or template ships without a five-platform binary release.
