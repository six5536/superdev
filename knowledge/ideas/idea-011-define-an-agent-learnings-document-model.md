# Idea: define an agent-learnings document model

Evaluate whether SOKF needs a dedicated schema and document set for agent
memory or learnings that are useful but not yet canonical project knowledge.
Define what belongs there, its lifecycle and review rules, and how useful
learnings are promoted into canonical knowledge—or conclude that existing
knowledge types are sufficient.

## Motivation

Agents can discover useful working information that does not obviously fit the
current canonical knowledge. It is unclear whether this is genuinely a
separate category: information useful enough to retain may simply be project
knowledge. A defined model would make that boundary explicit rather than
leaving each agent to invent one.

This remains separate from the existing knowledge-capture-skill idea, which
focuses on teaching agents when and how to record durable knowledge.

## Open questions

- What information is useful to future agents but unsuitable for canonical knowledge?
- Should agent learnings be a schema-backed document set, a lifecycle state, or neither?
- Who reviews learnings, and when are they promoted, expired, or discarded?
- How would the model avoid becoming a second, lower-quality knowledge store?
