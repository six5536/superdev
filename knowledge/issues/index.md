# Issues

## Externally sourced content packs

* [update can move a pin to a pack format this binary cannot read, and cannot move it back](I001-update-can-pin-an-unreadable-pack-format.md) - decided as ADR-013: update resolves a moved pin before saving the manifest and keeps the old pin when it refuses, which closes the class rather than the format case alone.
* [The default-source query has no time bound, so a black-holed network stalls update](I002-no-time-bound-on-the-update-query.md) - fixed in P005 slices 4 and 5: the spawn seam gained an options form of run carrying a timeout and an environment, and the query update makes unprompted is the one caller that sets one — five seconds, after which it reports the source unreachable and carries on.
* [Deleting an item from a local pack leaves its live copy in place, and the drift check stays green](I003-a-local-pack-cannot-remove-what-it-dropped.md) - wontfix: the layering rule stands, and the rebuild that a pack developer needs anyway is the answer — `cargo run -- sync` in one step.
* [A path pack's lock digest is rewritten by every content commit and verified by nothing](I004-a-path-packs-digest-churns-and-is-never-checked.md) - decided as ADR-016: the lock's digest becomes optional and a path source records none, since the value was written and read by nothing while rewriting one committed line on every content commit.
* [Sync re-records a hash only for a file it writes, so backporting an edit leaves the lock stale](I005-a-backport-leaves-the-lock-stale.md) - fixed in slice 17: a run reconciles every claim against what is on disk before saving the lock, after the engine so a real edit is still reported.
* [Content packs are absent from the user documentation, and the update command now describes itself wrongly](I006-content-packs-are-undocumented-for-users.md) - fixed in slice 18: the README gained a packs section, and update's description was corrected on every surface it reaches.
* [A pack source's scheme is unchecked, so the base pack can be fetched over a transport anyone on-path can answer](I007-a-pack-source-reaches-git-with-no-scheme-check.md) - fixed in P005 slice 1: the command-running half closed first, and ADR-012 closed the transport half — https, ssh and file allowlisted at parse and again in git's own protocol policy, with git, http and ext refused by name.
* [A symlinked file in a pack is followed, copying the target's contents into the repo](I008-a-symlinked-file-in-a-pack-is-followed.md) - fixed in slice 16: every symlink in a pack tree was skipped, and a linked pack root or manifest refused; P005 slices 2 and 3 turned the skip into a refusal, so the tree, the root and the manifest now follow one rule.
* [A symlink inside a pack is skipped in silence, so an item a pack meant to ship quietly disappears](I009-a-skipped-symlink-says-nothing.md) - fixed in P005 slices 2 and 3: a symlink anywhere in a pack is refused naming the path, and for a fetched pack git's index mode decides, which settles the Windows digest split and refuses a submodule with it.
