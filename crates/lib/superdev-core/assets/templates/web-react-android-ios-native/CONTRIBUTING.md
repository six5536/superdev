# Contributing

## Layout

- `apps/web` — TypeScript + React + Vite. Lint, tests and build all run from
  the repo root through npm workspaces.
- `apps/android-native` — Kotlin + Jetpack Compose. Unit tests run on the
  JVM (Robolectric included), so `./gradlew test` needs no emulator.
- `apps/ios-native` — Swift + SwiftUI. `project.yml` is the source of truth;
  the `.xcodeproj` is generated by xcodegen and `swift build`/`swift test`
  work without it.
- `libs/native-debug-server-android`, `libs/native-debug-server-ios` — an
  HTTP debug server compiled into debug builds only; `libs/debug-mcp-server`
  wraps its API as MCP tools so agents can drive a running app.
- `scripts/` — the dev CLI (`npm run android`, `npm run ios`,
  `npm run dev:all`), plus the host-side adb bridge under `scripts/host/`.

## The parity rule

The three apps are one product. A behaviour change lands on every platform —
same flows, same copy, same edge cases — or it doesn't land. Keep the
platform-specific code thin and the behaviour observable in tests, so drift
shows up as a failing test rather than a bug report.

## Dev container

`.devcontainer/` is the supported setup, but the tool versions are not its
to decide: Node, the JDK, Gradle and xcodegen are pinned in `mise.toml` at
the repo root, so `mise install` gets you the same versions outside the
container too. Bump a version there. The Android SDK packages come from
`mise run android-packages`, which the image build runs and `post-create`
re-runs as a drift check.

superdev writes its own pins into `.mise.toml`, next door. mise merges every
config it finds in a directory, so the two files coexist and neither
rewrites the other; `mise.toml` is yours.

Only git comes from a devcontainer feature, pinned by digest in
`devcontainer-lock.json`; refresh it with
`devcontainer upgrade --workspace-folder .`. The Dockerfile installs mise
from a pinned release checked against a committed SHA256 — bump both
together, the file says where the hashes come from.

`post-create.sh` installs everything the repo pins (`mise install`) and then
the two tools that belong to the container rather than the project —
`superdev` and Claude Code — into the container's global mise config.

Gradle caches, the iOS `.build` tree and `node_modules` live on named
volumes prefixed with the project slug, so parallel projects on one machine
never share them. To start from scratch,
`docker volume rm {{superdev:project-slug}}-gradle-cache`.

Shell scripts, `gradlew` and `.devcontainer/**` are forced to LF in
`.gitattributes`. bash and Docker both fail on CRLF, and a Windows checkout
would otherwise introduce it.

## Everyday commands

```sh
npm run lint            # eslint (web)
npm run test            # vitest (web)
npm run dev:all test    # tests on all three platforms
npm run android -- build|install|run|logs|screenshot
npm run ios -- build|install|run|logs|screenshot
npm run mcp:debug       # the debug MCP server (stdio)
```

## Releasing

`release/release.yaml` is the single source of truth for version, build
number and app id. `bundle exec fastlane bump_version type:patch` bumps it
and stamps every platform file; the tag-triggered
`.github/workflows/release.yml` runs the same `checks.yml` gate as CI and
then builds and uploads per platform. The full procedure, including the
GitHub secrets each platform needs, is in [docs/RELEASE.md](docs/RELEASE.md).
